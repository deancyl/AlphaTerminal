# API 认证说明

## 概述

AlphaTerminal API 采用**无认证**模式，所有端点均为公开访问。本文档说明当前的认证策略、Session 管理机制以及未来可能的扩展方向。

---

## 当前认证状态

### 无需认证的公开端点

所有 API 端点均无需认证即可访问：

```
GET  /api/v1/market/overview
GET  /api/v1/market/quote/{symbol}
GET  /api/v1/macro/overview
GET  /api/v1/news/flash
POST /api/v1/backtest/run
...
```

**设计原因**：

1. **本地部署优先**：AlphaTerminal 设计为本地化部署，用户在本地环境运行服务
2. **简化使用体验**：无需注册账户、无需 API Key、无需复杂配置
3. **开箱即用**：克隆仓库后一键启动即可访问所有功能

### 访问示例

```bash
# 直接访问，无需认证头
curl http://localhost:60100/api/v1/market/overview

# 响应
{
  "code": 0,
  "message": "success",
  "data": {
    "indices": [...],
    "sectors": [...]
  }
}
```

## Session 管理

虽然 API 无需认证，但部分功能使用 Session 进行状态管理。

### Session 创建

```http
POST /api/v1/session/create
Content-Type: application/json

{
  "user_id": "user-123",
  "config_version": 5
}
```

**响应**：

```json
{
  "code": 0,
  "data": {
    "session_id": "sess_abc123",
    "user_id": "user-123",
    "config_version": 5,
    "created_at": "2026-05-31T10:30:00",
    "expires_at": "2026-05-31T11:00:00"
  }
}
```

### Session 用途

| 功能模块 | Session 用途 |
|---------|-------------|
| **Copilot** | 绑定 LLM 配置版本、追踪 Token 消耗 |
| **Backtest** | 关联回测任务、记录执行历史 |
| **Strategy** | 绑定模型配置、追踪策略版本 |

### Session 生命周期

```
创建 Session → 绑定配置版本 → 使用功能 → 自动续期 → 超时过期
     │              │            │           │
     │              │            │           └── 30分钟无活动
     │              │            └── touch_session() 重置 TTL
     │              └── 绑定特定配置快照
     └── POST /api/v1/session/create
```

### Session API 端点

| 端点 | 方法 | 描述 |
|------|------|------|
| `/api/v1/session/create` | POST | 创建新 Session |
| `/api/v1/session/{id}` | GET | 获取 Session 状态 |
| `/api/v1/session/{id}/bind` | POST | 绑定模型到 Session |
| `/api/v1/session/{id}/extend` | POST | 延长 Session TTL |
| `/api/v1/session/{id}` | DELETE | 删除 Session |

### Session 代码示例

```python
# Python 示例
import requests

# 创建 Session
response = requests.post(
    "http://localhost:60100/api/v1/session/create",
    json={"user_id": "user-123", "config_version": 5}
)
session_id = response.json()["data"]["session_id"]

# 使用 Session
headers = {"X-Session-ID": session_id}
response = requests.post(
    "http://localhost:60100/api/v1/copilot/chat",
    headers=headers,
    json={"message": "分析茅台股票走势"}
)

# 延长 Session
requests.post(f"http://localhost:60100/api/v1/session/{session_id}/extend")
```

```javascript
// JavaScript 示例
// 创建 Session
const sessionResponse = await fetch('/api/v1/session/create', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ user_id: 'user-123', config_version: 5 })
})
const { data: session } = await sessionResponse.json()
const sessionId = session.session_id

// 使用 Session
const chatResponse = await fetch('/api/v1/copilot/chat', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'X-Session-ID': sessionId
  },
  body: JSON.stringify({ message: '分析茅台股票走势' })
})
```

## 未来认证扩展建议

随着 AlphaTerminal 的演进，可能需要以下认证扩展：

### 1. API Key 认证（推荐用于生产环境）

**使用场景**：多用户部署、云端服务

```http
GET /api/v1/market/overview
Authorization: Bearer YOUR_API_KEY
```

**实现建议**：

```python
# backend/app/middleware/api_key_auth.py
from fastapi import Header, HTTPException

async def verify_api_key(x_api_key: str = Header(None)):
    if not x_api_key or x_api_key != settings.API_KEY:
        raise HTTPException(status_code=401, detail="Invalid API Key")
    return x_api_key
```

### 2. JWT Token 认证

**使用场景**：用户登录、权限管理

```http
POST /api/v1/auth/login
Content-Type: application/json

{
  "username": "user@example.com",
  "password": "password123"
}

# 响应
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expires_in": 3600
}
```

### 3. OAuth 2.0 认证

**使用场景**：第三方集成（企业微信、钉钉等）

```
GET /api/v1/auth/oauth/authorize?provider=wechat
GET /api/v1/auth/oauth/callback?code=xxx&state=xxx
```

### 4. IP 白名单

**使用场景**：限制访问来源

```python
# backend/app/middleware/ip_whitelist.py
ALLOWED_IPS = ["127.0.0.1", "192.168.1.0/24"]

async def check_ip_whitelist(request: Request):
    client_ip = request.client.host
    if not is_ip_allowed(client_ip, ALLOWED_IPS):
        raise HTTPException(status_code=403, detail="IP not allowed")
```

### 5. 速率限制增强

**当前实现**：基于 IP 的速率限制

**未来增强**：基于用户/API Key 的速率限制

```python
# 不同用户等级不同限制
RATE_LIMITS = {
    "free": 100,      # 100 req/min
    "pro": 1000,      # 1000 req/min
    "enterprise": -1  # 无限制
}
```

### 1. 使用 HTTPS

```bash

# Nginx 配置示例

    listen 443 ssl;
    server_name api.yourdomain.com;
    
    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;
```

## 常见问题

### Q1: 为什么不需要认证？

**A**: AlphaTerminal 设计为本地化部署的投研终端，用户在本地运行服务，无需云端账户。这简化了使用体验，实现了开箱即用。

### Q2: 如何保护 API 安全？

**A**: 
1. 使用速率限制（默认启用）
2. 限制网络访问（仅 localhost）
3. 使用 HTTPS（生产环境）
4. 定期审计日志

### Q3: Session 和认证有什么区别？

**A**: 
- **认证**：验证用户身份（AlphaTerminal 当前无需认证）
- **Session**：管理用户状态（Copilot、Backtest 等功能使用）

### Q4: 多用户部署如何实现认证？

**A**: 参考"未来认证扩展建议"章节，实现 API Key 或 JWT 认证。
