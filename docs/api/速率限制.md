# API 速率限制说明

## 概述

AlphaTerminal 实现了基于 Token Bucket 算法的速率限制机制，防止 API 滥用、保护系统稳定性。本文档说明全局限制、特殊端点限制、429 响应格式以及 HTTP Headers。

---

## 速率限制策略

### 全局限制

所有 API 请求受全局速率限制保护：

| 参数 | 值 | 说明 |
|------|-----|------|
| **全局限制** | 200 req/60s | 默认每分钟最多 200 次请求 |
| **突发容量** | 150 tokens | Token Bucket 最大容量 |
| **填充速率** | 2.5 tokens/s | 每秒恢复 2.5 个令牌 |

### 算法说明

使用 **Token Bucket（令牌桶）** 算法：

```
初始状态: 150 tokens（突发容量）
     │
     ├─ 每秒填充 2.5 tokens
     │
     ├─ 每次请求消耗 1 token
     │
     └─ tokens = 0 时，返回 429
```

**优势**：
- 允许突发请求（短时间内可发送 150 次请求）
- 持续请求时，限制为 150 req/min（2.5 × 60）
- 比 Fixed Window 更平滑，无边界突发问题

## 429 响应格式

当触发速率限制时，API 返回 HTTP 429 状态码：

### 响应示例

```json
{
  "code": 120,
  "message": "请求过于频繁，请稍后重试",
  "data": null,
  "error": {
    "details": {
      "retry_after": 60,
      "limit": 200,
      "remaining": 0,
      "reset": 1699999999
    },
    "trace_id": "abc12345",
    "timestamp": "2026-05-31T10:30:00"
  },
  "timestamp": "2026-05-31T10:30:00"
}
```

### HTTP Headers

速率限制信息通过 HTTP Headers 返回：

```http
HTTP/1.1 429 Too Many Requests
Content-Type: application/json
X-RateLimit-Limit: 200
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 1699999999
Retry-After: 60
```

| Header | 说明 | 示例值 |
|--------|------|--------|
| `X-RateLimit-Limit` | 时间窗口内最大请求数 | 200 |
| `X-RateLimit-Remaining` | 剩余请求数 | 0 |
| `X-RateLimit-Reset` | Unix 时间戳，限制重置时间 | 1699999999 |
| `Retry-After` | 建议等待秒数 | 60 |

## 实现细节

### Token Bucket 算法

**文件位置**: `backend/app/middleware/rate_limit_token_bucket.py`

```python
class TokenBucketRateLimiter:
    """Token Bucket 速率限制器"""
    
    def __init__(self, capacity: int = 150, refill_rate: float = 2.5):
        self.capacity = capacity
        self.refill_rate = refill_rate
        self._buckets: Dict[str, Dict] = {}  # key -> {tokens, last_refreshed}
    
    def check_rate_limit(self, key: str) -> Tuple[bool, Dict]:
        """检查是否允许请求"""
        now = time.time()
        
        if key not in self._buckets:
            self._buckets[key] = {
                "tokens": self.capacity,
                "last_refreshed": now
            }
        
        bucket = self._buckets[key]
        elapsed = now - bucket["last_refreshed"]
        
        # Refill tokens
        bucket["tokens"] = min(
            self.capacity,
            bucket["tokens"] + elapsed * self.refill_rate
        )
        bucket["last_refreshed"] = now
        
        if bucket["tokens"] >= 1:
            bucket["tokens"] -= 1
            return True, self._get_headers(bucket)
        else:
            return False, self._get_headers(bucket)
```

### SQLite 持久化

速率限制状态持久化到 SQLite：

```sql
CREATE TABLE token_buckets (
    key TEXT PRIMARY KEY,
    tokens REAL NOT NULL,
    last_refreshed REAL NOT NULL
)
```

**优势**：
- 多进程共享状态
- 服务重启后保持限制状态
- 支持分布式部署

### 2. 处理 429 响应

```python
import time

def api_request_with_retry(url, max_retries=3):
    for attempt in range(max_retries):
        response = requests.get(url)
        
        if response.status_code == 200:
            return response.json()
        
        if response.status_code == 429:
            retry_after = int(response.headers.get("Retry-After", 60))
            print(f"Rate limited, waiting {retry_after}s...")
            time.sleep(retry_after)
            continue
        
        raise Exception(f"API error: {response.status_code}")
    
    raise Exception("Max retries exceeded")
```

### 3. 前端 Circuit Breaker

```javascript
// frontend/src/utils/api.js
const _CIRCUIT_THRESHOLD = 5
const _DEGRADE_THRESHOLD = 3

let _consecutiveFailures = 0
let _isDegraded = false

async function apiFetch(url, options) {
    if (_isDegraded) {
        throw new Error('Circuit breaker: API is in degraded mode')
    }
    
    try {
        const response = await fetch(url, options)
        
        if (response.status === 429) {
            _consecutiveFailures++
            if (_consecutiveFailures >= _DEGRADE_THRESHOLD) {
                _isDegraded = true
            }
            throw new Error('Rate limited')
        }
        
        _consecutiveFailures = 0
        return response
    } catch (error) {
        _consecutiveFailures++
        if (_consecutiveFailures >= _CIRCUIT_THRESHOLD) {
            _isDegraded = true
        }
        throw error
    }
}
```

### 4. 批量请求策略

```python
# 批量请求时，控制请求速率
import asyncio
import aiohttp

async def batch_requests(urls, batch_size=10, delay=0.1):
    results = []
    
    for i in range(0, len(urls), batch_size):
        batch = urls[i:i+batch_size]
        
        async with aiohttp.ClientSession() as session:
            tasks = [session.get(url) for url in batch]
            responses = await asyncio.gather(*tasks)
            results.extend(responses)
        
        # 批次间延迟
        await asyncio.sleep(delay)
    
    return results
```

## 常见问题

### Q1: 为什么使用 Token Bucket 而不是 Fixed Window？

**A**: 
- **Token Bucket**：允许突发请求，更平滑的限制
- **Fixed Window**：边界突发问题（在窗口末尾和开头可以发送 2 倍请求）

### Q2: 速率限制如何处理多个 IP？

**A**: 当前基于 IP 地址区分客户端，不同 IP 有独立的令牌桶。

### Q3: 如何临时禁用速率限制？

**A**: 
```bash
# 设置环境变量
export RATE_LIMIT_ENABLED=false

# 或在 Admin API 中禁用（未来功能）
POST /api/v1/admin/rate_limit/disable
```

### Q4: WebSocket 是否受速率限制？

**A**: WebSocket 连接有独立的消息速率限制（100 msg/s），详见 [WebSocket协议.md](./WebSocket协议.md)。
