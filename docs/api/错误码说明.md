# API 错误码说明

## 概述

AlphaTerminal 使用统一的错误码体系，便于客户端识别和处理错误。本文档说明 ErrorCode 枚举定义、错误码分类、HTTP 状态码映射以及错误响应格式。

---

## 错误码分类

错误码采用分层设计：

| 范围 | 分类 | 说明 |
|------|------|------|
| **0** | 成功 | 请求成功 |
| **1xx** | 客户端错误 | 参数错误、认证失败等 |
| **2xx** | 服务端错误 | 内部错误、数据库错误等 |
| **3xx** | 第三方服务错误 | API 调用失败、数据源错误等 |
| **4xx** | 业务逻辑错误 | 数据不足、策略错误等 |

## ErrorCode 枚举定义

**文件位置**: `backend/app/utils/errors.py`

### 成功 (0)

| 错误码 | 常量名 | 说明 |
|--------|--------|------|
| 0 | `SUCCESS` | 请求成功 |

### 客户端错误 (1xx)

| 错误码 | 常量名 | 说明 | 常见原因 |
|--------|--------|------|----------|
| 100 | `BAD_REQUEST` | 请求参数错误 | 缺少必需参数、参数格式错误 |
| 101 | `UNAUTHORIZED` | 未授权访问 | 缺少认证信息或认证失败 |
| 102 | `FORBIDDEN` | 禁止访问 | 无权限访问该资源 |
| 104 | `NOT_FOUND` | 资源不存在 | 请求的股票、接口不存在 |
| 105 | `METHOD_NOT_ALLOWED` | 方法不允许 | 使用了错误的 HTTP 方法 |
| 110 | `VALIDATION_ERROR` | 数据验证失败 | 参数验证不通过 |
| 120 | `RATE_LIMITED` | 请求频率限制 | 触发速率限制 |

### 服务端错误 (2xx)

| 错误码 | 常量名 | 说明 | 常见原因 |
|--------|--------|------|----------|
| 200 | `INTERNAL_ERROR` | 内部服务器错误 | 未预期的异常 |
| 210 | `DATABASE_ERROR` | 数据库错误 | SQL 执行失败、连接失败 |
| 220 | `CACHE_ERROR` | 缓存错误 | Redis 连接失败、缓存读写错误 |
| 230 | `CONFIG_ERROR` | 配置错误 | 配置项缺失或格式错误 |

### 第三方服务错误 (3xx)

| 错误码 | 常量名 | 说明 | 常见原因 |
|--------|--------|------|----------|
| 302 | `THIRD_PARTY_ERROR` | 第三方服务通用错误 | 外部服务调用失败 |
| 310 | `TIMEOUT_ERROR` | 请求超时 | API 响应时间超过限制 |
| 320 | `API_ERROR` | API 调用错误 | 外部 API 返回错误 |
| 330 | `DATA_SOURCE_ERROR` | 数据源错误 | AkShare、东方财富等数据源异常 |
| 340 | `SERVICE_UNAVAILABLE` | 服务暂不可用 | 数据源熔断、服务降级 |

### 业务逻辑错误 (4xx)

| 错误码 | 常量名 | 说明 | 常见原因 |
|--------|--------|------|----------|
| 400 | `BUSINESS_ERROR` | 业务通用错误 | 业务规则验证失败 |
| 410 | `INSUFFICIENT_DATA` | 数据不足 | 缺少计算所需的数据 |
| 420 | `CALCULATION_ERROR` | 计算错误 | 指标计算失败、除零错误 |
| 430 | `STRATEGY_ERROR` | 策略执行错误 | 策略代码执行异常 |

## HTTP 状态码映射

### 映射规则

FastAPI 的 HTTP 状态码自动映射为 ErrorCode：

| HTTP 状态码 | ErrorCode | 说明 |
|-------------|-----------|------|
| 200 | `SUCCESS (0)` | 成功 |
| 400 | `BAD_REQUEST (100)` | 参数错误 |
| 401 | `UNAUTHORIZED (101)` | 未授权 |
| 403 | `FORBIDDEN (102)` | 禁止访问 |
| 404 | `NOT_FOUND (104)` | 资源不存在 |
| 405 | `METHOD_NOT_ALLOWED (105)` | 方法不允许 |
| 422 | `VALIDATION_ERROR (110)` | 数据验证失败 |
| 429 | `RATE_LIMITED (120)` | 请求频率限制 |
| 500 | `INTERNAL_ERROR (200)` | 内部错误 |

### 映射代码

```python
# backend/app/utils/errors.py
def http_exception_handler(exc: HTTPException) -> Dict[str, Any]:
    code_map = {
        400: ErrorCode.BAD_REQUEST,
        401: ErrorCode.UNAUTHORIZED,
        403: ErrorCode.FORBIDDEN,
        404: ErrorCode.NOT_FOUND,
        405: ErrorCode.METHOD_NOT_ALLOWED,
        422: ErrorCode.VALIDATION_ERROR,
        429: ErrorCode.RATE_LIMITED,
        500: ErrorCode.INTERNAL_ERROR,
    }
    
    code = code_map.get(exc.status_code, ErrorCode.INTERNAL_ERROR)
    return error_response(code, exc.detail)
```

## 错误响应格式

### 标准格式

所有 API 响应遵循统一格式：

```json
{
  "code": 0,
  "message": "success",
  "data": { ... },
  "error": null,
  "timestamp": "2026-05-31T10:30:00.123456"
}
```

### 错误响应格式

```json
{
  "code": 100,
  "message": "请求参数错误",
  "data": null,
  "error": {
    "details": {
      "field": "symbol",
      "reason": "股票代码格式错误"
    },
    "trace_id": "abc12345",
    "timestamp": "2026-05-31T10:30:00"
  },
  "timestamp": "2026-05-31T10:30:00"
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | int | 错误码（0 表示成功） |
| `message` | string | 错误消息 |
| `data` | object/null | 成功时返回数据，错误时为 null |
| `error` | object/null | 错误时返回详情，成功时为 null |
| `error.details` | object | 错误详细信息 |
| `error.trace_id` | string | 追踪 ID（用于日志关联） |
| `error.timestamp` | string | 错误发生时间 |
| `timestamp` | string | 响应时间 |

## 客户端错误处理

### Python 示例

```python
import requests

def api_request(url):
    response = requests.get(url)
    data = response.json()
    
    if data["code"] == 0:
        return data["data"]
    
    # 处理错误
    code = data["code"]
    message = data["message"]
    trace_id = data["error"]["trace_id"]
    
    if code == 100:
        raise ValueError(f"参数错误: {message}")
    elif code == 104:
        raise NotFoundError(f"资源不存在: {message}")
    elif code == 120:
        retry_after = data["error"]["details"].get("retry_after", 60)
        raise RateLimitError(f"速率限制，等待 {retry_after}s")
    elif code == 200:
        raise InternalError(f"服务器错误 (trace_id: {trace_id})")
    else:
        raise APIError(f"未知错误: {message}")
```

### JavaScript 示例

```javascript
class APIError extends Error {
  constructor(code, message, details, traceId) {
    super(message)
    this.name = 'APIError'
    this.code = code
    this.details = details
    this.traceId = traceId
  }
}

async function apiRequest(url) {
  const response = await fetch(url)
  const data = await response.json()
  
  if (data.code === 0) {
    return data.data
  }
  
  throw new APIError(
    data.code,
    data.message,
    data.error?.details,
    data.error?.trace_id
  )
}

// 使用示例
try {
  const quote = await apiRequest('/api/v1/market/quote/sh600519')
} catch (error) {
  if (error instanceof APIError) {
    switch (error.code) {
      case 100:
        console.error('参数错误:', error.message)
        break
      case 120:
        const retryAfter = error.details?.retry_after || 60
        console.error(`速率限制，等待 ${retryAfter}s`)
        break
      default:
        console.error(`错误 ${error.code}:`, error.message)
    }
  }
}
```

## 常见问题

### Q1: 错误码和 HTTP 状态码有什么区别？

**A**: 
- **HTTP 状态码**：传输层语义（200 OK, 404 Not Found 等）
- **ErrorCode**：业务层语义（更细粒度的错误分类）

### Q2: 如何区分业务错误和网络错误？

**A**: 
- **业务错误**：HTTP 200，`code != 0`
- **网络错误**：HTTP 非 200，或连接失败

### Q3: trace_id 有什么用？

**A**: 用于关联前后端日志，便于问题排查。客户端可使用 trace_id 查询错误详情。
